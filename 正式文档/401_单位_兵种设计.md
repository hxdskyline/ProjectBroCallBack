# 兵种设计

版本：v2.0

---

## 一、系统概述

兵种是战斗的核心单位。每个兵种拥有**稀有度**、**强化等级**和**固定被动**三大核心属性，三者共同决定兵种的定位和强度。

**设计原则**：
- 数值不膨胀，机制做质变：成长不是堆砌攻击力，而是通过触发稳定性、机制联动和圣物放大来产生"配合倍率"的爽感
- 理解简单，构筑有深度：稀有度体系与强化规则一目了然，但圣物与稀有兵种提供了充足的 synergies 探索空间
- 权衡无处不在：温泉二选一、换血时机、三选一抉择等贯穿全流程

---

## 二、稀有度体系

兵种分为三个稀有度：**普通**、**高级**、**稀有**。

| 稀有度 | 设计定位 | 机制特点 | 获得途径 |
|--------|---------|---------|---------|
| **普通** | 基础机制载体，前期的建队基石 | 技能触发不稳定（概率触发、限时触发） | 常规战斗招募（第一关主要来源） |
| **高级** | 普通兵种的机制升级版，触发更稳定，中期替换与过渡核心 | 技能触发条件更稳定（条件触发，可控可达成） | 战斗招募，越后期出现越频繁 |
| **稀有** | 机制联动核心，构筑的终极引擎 | 依赖场上其他单位的特定机制触发联动效果 | Boss关固定三选一；非Boss关极低概率出现 |

### 2.1 普通兵种

- **逻辑关系**：普通兵种是高级兵种的劣化版
- **机制特点**：技能触发不稳定
  - 难以和其他逻辑combo（如：前三秒攻速+100%）
  - 概率触发（如：30%概率触发分裂攻击）
- **被动**：功能性被动，效果朴素（如"前三秒攻速+100%"）

### 2.2 高级兵种

- **逻辑关系**：高级兵种为逻辑combo基准
- **机制特点**：技能触发条件更稳定
  - 由"概率触发"变为"条件触发"（如：身上每层狂暴buff有20%概率触发分裂攻击）
  - 条件更可控，更易达成
- **被动**：数值略高或有轻微机制优化（如"场上有存活的橘猫，攻速+70%"）

### 2.3 稀有兵种

- **逻辑关系**：稀有兵种为逻辑combo的爽版
- **机制特点**：自身技能依赖场上其他单位使用特定机制
  - 如"每当场上有单位触发分裂攻击，则召唤一枚陨石，2s冷却"
- **被动**：强力联动被动，与特定机制深度绑定（如"同时享受场上所有橘猫的被动效果"）
- **定位**：构筑"化学反应链"的终极组件

## 三、概率分布

### 3.1 各大关出现概率

| 稀有度 | 第一关（1~15层） | 第二关（16~30层） | 第三关（31~45层） | 备注 |
|--------|-----------------|------------------|------------------|------|
| **普通** | 69% | 30% | 10% | 基础不稳 |
| **高级** | 30% | 67% | 大量 | 稳定升级版 |
| **稀有（非Boss）** | 1% | 3% | 5% | 机制核心；Boss关固定掉落三选一 |

### 3.2 天生强化概率

| 稀有度 | 第一关 | 第二关 | 第三关 |
|--------|--------|--------|--------|
| **普通** | 0% | 35% | 100% |
| **高级** | 0% | 35% | 65% |
| **稀有** | 0% | 0% | 30%（仅非Boss） |

- **天生强化**：该兵种出现时直接为强化版（1级状态），无需额外消耗
- 第一关出现的兵种均为未强化形态（0级）

## 四、强化系统

### 4.1 强化规则

强化仅在**温泉场景**的强制二选一中触发（详见选关文档温泉节点描述）：

| 选项 | 效果 | 说明 |
|------|------|------|
| **选项A：集体泡温泉** | 全体单位生命值回满 | 当下安全 |
| **选项B：猫薄荷精华** | 选择一名兵种，将其从 0 级升至 1 级 | 未来战力 |

**关键约束**：
- 此二选一不可兼得，选择后不可反悔
- 猫薄荷精华不可保留、不可带走，必须当场使用
- 只能对 0 级兵种使用（已强化兵种不可再次强化）

### 4.2 强化效果

| 强化项目 | 效果 |
|---------|------|
| 全属性 | +50% |
| 技能机制 | 不变 |
| 被动效果 | 通常不变（0级和1级完全一致） |

> **设计说明**：被动通常不随强化提升，这是设计方案。但实现时需要支持被动随强化提升，以便特殊兵种的设计需求。

### 4.3 设计意图

强制玩家在"当下安全"与"未来战力"之间做出战略权衡。越是追求极限强度，越需要放弃恢复，增加后续关卡的风险。

---

## 五、被动系统

每个兵种拥有**一个固定被动技能**，根据稀有度和机制设计。

### 5.1 被动与强化关系

- 被动通常不随强化（等级）变化，0级和1级完全一致
- 实现层需支持被动随强化提升（部分特殊兵种可能需要）
- 维持兵种的核心辨识度，降低玩家认知负担

### 5.2 按稀有度的被动设计

| 稀有度 | 被动特点 | 示例 |
|--------|---------|------|
| **普通** | 功能性被动，效果朴素 | "前三秒攻速+100%" |
| **高级** | 数值略高或有轻微机制优化 | "场上有存活的橘猫，攻速+70%" |
| **稀有** | 强力联动被动，与特定机制深度绑定 | "同时享受场上所有橘猫的被动效果" |

## 七、构筑节奏总览

### 第一关（1~15层）

- 主要收集**普通兵种**，搭建基础阵容
- 少量**高级兵种**初次亮相，为后续转型埋下伏笔
- 无稀有兵种（非Boss 1%概率极低），但有圣物（普通圣物），玩家开始围绕机制标签调整阵容
- 温泉抉择首次出现，决定是否开始投资强化
- 击败本关Boss获得**第一个稀有兵种**（三选一），构筑方向初定
- 获得Boss专属圣物

### 第二关（16~30层）

- 普通兵种仍有出现（30%），部分天生强化，开始被高级逐步取代
- 高级兵种成为主力过渡，未强化高级兵不如强化普通兵
- 可获得圣物（普通圣物、高级圣物、少量稀有圣物）
- 获得Boss专属圣物

### 第三关（31~45层）

- 普通兵种基本退出舞台（10%）
- 高级兵种大量且多半自带强化，成为中坚力量
- 稀有兵种多次出现（5%），配合圣物形成完全体联动
- 可获得圣物（高级圣物、少量稀有圣物）
- 最终构筑成型，迎接最终Boss战
- 获得Boss专属圣物

## 八、数据结构

### 8.1 稀有度枚举

```
enum Rarity
├── Normal = 0    // 普通
├── Advanced = 1  // 高级
└── Rare = 2      // 稀有
```

### 8.2 强化等级

```
enum EnhanceLevel
├── Level0 = 0    // 未强化
└── Level1 = 1    // 已强化（全属性+50%）
```

### 8.3 UnitConfig 更新

```
UnitConfig {
    unitId:         单位唯一 ID
    name:           显示名
    species:        物种（Cat / Dog / Bird / Other）
    weightClass:    重量级标签（Light / Medium / Heavy，可多个）
    populationCost: 人口消耗（在 fighter_config.json 中配置）
    rarity:         稀有度（Rarity 枚举，0=普通/1=高级/2=稀有）
    enhanceLevel:   强化等级（0 或 1）
    maxHp:          生命值（基础值，强化后 ×1.5）
    attack:         攻击力（基础值，强化后 ×1.5）
    attackSpeed:    攻击速度（基础值，强化后 ×1.5）
    moveSpeed:      移动速度（基础值，强化后 ×1.5）
    passiveSkillId: 被动技能 ID
    tags:           标签列表（如 ["cat", "melee", "flying"]）
    mechanismTag:   机制标签（如 "split_attack"、"shield"，用于圣物系统匹配）
    avatarId:       外观 ID
}
```

### 8.4 招募概率配置

```
RaritySpawnConfig {
    regionId:       所属大关（1~3）
    rarity:         稀有度
    spawnRate:      出现概率（0.0~1.0）
    bornEnhanceRate: 天生强化概率（0.0~1.0）
}
```
