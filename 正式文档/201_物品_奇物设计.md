# 奇物系统设计

版本：v4.1

---

## 一、系统概述

奇物是局内永久生效的强力道具，对**所有兵种**生效。每个奇物提供强大的全局增益效果。奇物在战斗胜利后掉落，或通过特殊事件获得。

现有奇物：猫爬架（全体 HP+500）、苍蝇拍（全体 ATK+20）。

奇物按功能分为两类：
- **属性奇物**：直接提供属性加成（攻击力、防御力、生命值等）
- **圣物**：修改游戏全局规则的道具，增强特定**机制标签**（详见下方第八节）

## 四、命名规范

- 所有奇物 ID 前缀 `Artifact_`
- 现有奇物保留原 ID（`Artifact_LeaderHpFlat`、`Artifact_CatAttackFlat`）
- 新增奇物按效果命名，格式：`Artifact_` + 效果缩写
- 名称使用猫主题词汇（猫爪、猫魂、猫灵等），与现有物品风格一致

## 五、掉落规则

### 5.1 掉落时机

战斗胜利后，根据难度决定是否掉落奇物。

### 5.2 掉落池分层

| 掉落池 | 包含奇物 | 掉落率 |
|--------|---------|--------|
| `battle_normal` | #1~#8（纯属性） | 10% |
| `battle_hard` | #9~#16（双属性） | 15% |
| `battle_boss` | #17~#20（特效） + 现有疾风之靴/亡猫之力 | 20% |
| `prayer_free` | #1~#3 | 固定 |
| `prayer_low` | #4~#6 | 固定 |
| `prayer_high` | #7~#8, #9~#20 | 固定 |
| `relic_normal` | 普通圣物 | 按关卡概率 |
| `relic_advanced` | 高级圣物 | 按关卡概率 |
| `relic_rare` | 稀有圣物 | 按关卡概率（极低） |
| `relic_boss` | Boss 圣物 | Boss 关击败后固定掉落 |

### 5.3 掉落限制

- 每局最多携带 **5 个**奇物（可配置）
- 已拥有的奇物不会重复掉落
- 掉落时从对应池中随机抽取 1 个

## 六、与现有系统的关系

### 6.1 与旧饰品系统的关系

旧饰品系统（accessory_1~14）为**种族限定**饰品，只对特定种族生效。奇物系统为**全体**生效的更强道具。两套系统并行存在，旧饰品保持不变。

### 6.2 buff 管线集成

奇物效果在 `RebuildAuraBuffs()` 中与 affix buff 一起重建，写入 `RuntimeAttributes.ActiveBuffs`，参与 `Recalculate()` 计算。特效类奇物（type:15）需要在 `BattleSimulation` 中添加对应的触发逻辑。

## 七、实现要点

### 7.1 数据结构

`accessory_config.json` 新增条目，使用现有 `effects` 数组格式。特效类奇物需要新增 `subType` 字段区分触发逻辑。

### 7.2 特效触发

| subType | 触发位置 | 逻辑 |
|---------|---------|------|
| `KillHeal` | `BattleSimulation` 击杀结算 | 击杀时回复 maxHP × value |
| `DamageReduce` | `BattleSimulation.UpdatePendingHit` | 最终伤害 × (1 - value) |
| `LowHpBonus` | `BattleSimulation` 每 tick | 检查 HP% < 30%，添加 ATK% buff |
| `KillShield` | `BattleSimulation` 击杀结算 | 为全体队友添加 value 吸收量的护盾 |

### 7.3 持久化

奇物记录存储在 `PlayerData.runAccessories`（已有的 `EquipmentRecord` 列表），跨战斗持久，局结束清空。与现有 `RebuildAuraBuffs()` 集成，加载时自动重建效果。

## 八、圣物系统

### 8.1 设计核心

圣物是**修改游戏全局规则**的道具，非针对单个兵种。

- 效果作用于**所有满足条件的兵种**
- 遵循"规则统一，但越稀有的兵种收益越大"原则
- 圣物通过 `mechanismTag` 字段匹配兵种

### 8.2 运作逻辑

圣物会直接增强某一**机制标签**（如"分裂攻击"、"击退"、"护盾"）。

- 兵种技能描述中若包含该机制标签，则自动受益
- 因为稀有兵种基础触发更稳定、效果更强，所以从圣物中获得的绝对收益往往更大

### 8.3 圣物稀有度分层

| 稀有度 | 获取途径 | 说明 |
|--------|---------|------|
| **普通圣物** | 第一关~第三关战斗掉落 | 基础机制增强 |
| **高级圣物** | 第二关~第三关战斗掉落 | 较强机制增强 |
| **稀有圣物** | 第二关~第三关少量掉落 | 强力机制增强 |
| **Boss 圣物** | 仅 Boss 关击败后产出 | 全游戏仅 Boss 关产出，最强机制改写 |

### 8.4 Boss 圣物

- 全游戏仅 Boss 关产出，每次击败 Boss 获得 1 个
- Boss 圣物是最强力的规则改写道具
- 3 个 Boss 分别掉落不同的 Boss 圣物

| 第三关（31~45层） | 高级圣物、少量稀有圣物 |
| Boss 关（第15/30/45层） | Boss 专属圣物 |

## 九、实现要点（圣物）

### 9.1 机制标签

圣物通过 `mechanismTag` 字段匹配兵种。每个兵种在 `fighter_config.json` 中配置 `mechanismTags`（如 ["split", "bounce"]），圣物效果自动应用于拥有相同机制标签的兵种。

### 9.2 圣物数据结构

```
RelicConfig {
    relicId:        圣物唯一 ID
    name:           显示名
    description:    描述
    rarity:         圣物稀有度（0=普通/1=高级/2=稀有/3=Boss）
    mechanismTag:   增强的机制标签（如 "split_attack"，全局圣物为 null）
    effectType:     效果类型枚举
    value:          效果数值
    isBossRelic:    是否 Boss 专属圣物
}
```

### 9.3 圣物效果应用

圣物效果在 `RebuildAuraBuffs()` 中应用，逻辑如下：
1. 遍历所有已持有的圣物
2. 获取圣物的 `mechanismTag`
3. 查找所有拥有相同 `mechanismTag` 的兵种
4. 为匹配的兵种添加圣物效果 buff
